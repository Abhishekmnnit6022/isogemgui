2. FILE-BY-FILE BREAKDOWN AND FUNCTION DESCRIPTIONS

CORE PACKAGE (core/)

File: core/bezier.py
Description:
Pure math functions for Bernstein polynomials, arbitrary degree 2D and 3D Bezier curves, and 3D tensor-product Bezier surfaces.
Functions:
- bernstein(i, n, u):
  Calculates the value of the i-th Bernstein basis polynomial of degree n for an array of parameter values u in [0, 1].
- bezier_curve(control_points, n_eval=200):
  Takes an array of control points (2D or 3D) and returns points along the Bezier curve evaluated at n_eval parameter steps.
- bezier_surface(net, u_eval=30, v_eval=30):
  Takes a 3D control net grid of shape (rows, cols, 3) and computes the X, Y, and Z matrices of the evaluated 3D surface.

File: core/bspline.py
Description:
Pure math functions for B-spline basis functions and curve evaluation using the Cox-de Boor recursion algorithm.
Functions:
- _basis_scalar(i, p, u, knots):
  Recursively calculates the value of the i-th B-spline basis function of degree p at a single parameter value u. Handles zero division and includes the right endpoint u == knots[-1].
- basis_matrix(knots, degree, n_eval=200):
  Generates a matrix of all basis functions evaluated over an evenly spaced parameter array from the first knot to the last knot.
- bspline_curve(knots, degree, control_points, n_eval=200):
  Multiplies the evaluated basis functions with the control points to return the coordinates of points along the B-spline curve.

File: core/knots.py
Description:
Generators for standard knot vectors used in B-spline curves.
Functions:
- open_uniform(n_control_points, degree):
  Generates a clamped open uniform knot vector where the first (degree + 1) knots are 0 and the last (degree + 1) knots are 1, with evenly spaced values in between. This makes the curve pass through the first and last control points.
- uniform(n_control_points, degree):
  Generates an integer sequence of knots 0, 1, 2, ..., n + p, used for periodic or uniform B-splines.

File: core/validation.py
Description:
Input checking functions that verify data before calculation, raising clear ValueError messages if something is wrong.
Functions:
- validate_knots(knots):
  Verifies that knots are in non-decreasing order and that there are at least 2 knots.
- validate_degree(degree):
  Verifies that the polynomial degree is an integer greater than or equal to 0.
- validate_control_points(points):
  Verifies that control points form a valid 2D array with either 2 or 3 columns (X, Y or X, Y, Z).
- validate_bspline_params(knots, degree, n_control_points):
  Verifies the B-spline rule: len(knots) must equal n_control_points + degree + 1.
- validate_surface_net(net):
  Verifies that a surface control net has shape (rows, cols, 3) and is at least 2x2.

File: core/io_json.py
Description:
Handles saving and loading curve and surface data to and from JSON files.
Functions:
- _make_weights(n):
  Creates a list of 1.0 weights for all points (prepared for future NURBS support).
- save(path, data):
  Saves geometry dictionaries (control points, degree, knots, weights) into a JSON file.
- load(path):
  Reads a JSON file, validates its fields, and returns a verified dictionary with numpy arrays.


UI PACKAGE (ui/)

File: ui/bezier_tab.py
Description:
PyQt5 tab for 2D and 3D Bezier curves. Contains control point inputs, a table of points, degree counter, Draw button, and an embedded Matplotlib canvas.
Functions / Methods:

Functions / Methods:

- _load_default_preset(): Loads the 3x3 test control net from previous repository code.
- get_control_net(): Reads table rows into a 3D numpy array of shape (rows, cols, 3).
- set_control_net(net): Populates the table and spinboxes from a 3D numpy array.
- get_data(): Returns a surface dictionary for JSON saving.
- set_data(data): Populates the tab from loaded JSON data.

Functions / Methods:

- _add_point(): Adds a control point to the table.

================================================================================
3. WHAT LOGIC CHANGED FROM PREVIOUS CODE
================================================================================

1. In-Process Execution instead of Subprocesses:
   - Previously: main.py was a launcher that spawned external scripts using Python subprocesses (subprocess.Popen). Many scripts opened separate console windows or standalone dialogs.
   - Now: Everything runs inside one single window with 3 tabs. Calculations are called directly as in-memory Python functions.

2. Fixed Deprecated NumPy Functions:
   - Previously: Scripts used np.math.factorial or np.math.comb. In modern NumPy versions (2.0+), np.math has been removed and causes crash errors.
   - Now: Replaced with the standard Python math.comb function, which is fast, exact, and works on all Python versions.

3. Right-Endpoint Inclusion in B-Splines:
   - Previously: Cox-de Boor implementations used strict inequality (knots[i] <= u < knots[i+1]). When u reached the last knot (e.g. u = 1.0 or u = 5.0), all basis functions became 0, so the curve dropped to (0, 0) instead of reaching the last control point.
   - Now: An explicit check includes u == knots[-1] for the last active span, allowing clamped curves to touch the final control point as mathematically intended.

4. Unified B-Spline Basis Function Calculation:
   - Previously: There were multiple separate files (Basis_function.py, Bspline_Basis_function.py, Basis_test.py, BsplineCurve02.py) with slightly different implementations.
   - Now: Merged into one thoroughly tested, robust implementation in core/bspline.py.

5. Unified Excel Export:
   - Previously: Data_Store.py was a standalone script writing a hardcoded matrix to an Excel file path.
   - Now: Integrated as an interactive button on the B-spline tab and a menu item under File -> "Export basis matrix to Excel...". It lets the user choose any file destination and writes the computed basis matrix with column names.

6. Arbitrary Degree Bezier Curves:
   - Previously: There were separate files for 1st degree, 2nd degree, 3rd degree, and 3D cubic curves.
   - Now: One single formula evaluates any degree (from degree 1 up to high degrees) in both 2D and 3D.


================================================================================
4. WAS THE MATHEMATICS CHANGED OR NOT?
================================================================================

NO. The mathematics was NOT changed.
The underlying mathematical formulas remain identical:
- Bezier curves still use Bernstein polynomials:
    B_{i,n}(u) = C(n, i) * u^i * (1 - u)^(n - i)
- Bezier surfaces still use tensor products of Bernstein polynomials:
    S(u, v) = sum_i sum_j B_{i,n}(u) * B_{j,m}(v) * P_{i,j}
- B-splines still use the standard Cox-de Boor recurrence relation:
    N_{i,0}(u) = 1 if knots[i] <= u < knots[i+1], else 0
    N_{i,p}(u) = ((u - knots[i]) / (knots[i+p] - knots[i])) * N_{i,p-1}(u)
               + ((knots[i+p+1] - u) / (knots[i+p+1] - knots[i+1])) * N_{i+1,p-1}(u)
    with 0/0 defined as 0.
- All evaluation results were checked against the Matlab validation scripts and give identical numerical results.
