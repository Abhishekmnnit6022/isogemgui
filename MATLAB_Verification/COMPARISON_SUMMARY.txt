IGA DESIGNER - MATLAB VERIFICATION (SHORT SUMMARY)
==================================================

WHAT WAS DONE
  The software's IGA Analysis results were calculated a second time with
  separate MATLAB code that does not use any of the software's code. The two
  sets of results were then compared number by number.
  22 test shapes were checked, with 588 comparisons in total.
  (Run in GNU Octave 11.3, a free MATLAB-compatible program. MATLAB was not
  installed on this PC.)

RESULT
  All 588 comparisons MATCH. The largest difference is about 0.000000000000005
  (5e-15), which is just computer rounding. So the software's results are
  correct.
  One small bug was found on the way, fixed, and checked again (see image 09
  and image 12).


WHAT WAS COMPARED (SOFTWARE vs MATLAB)
  - Refined mesh       new knots and control points after splitting elements
  - Shape              the shape must not change when the mesh is refined
  - Surface points     x, y, z at many points
  - Jacobian (J)       how much each element is stretched (used for mesh quality)
  - Elements           how many there are, and which control points each one uses
  - Boundaries         which control points lie on each edge
  - Unknowns (DOFs)    number of unknowns a solver would have
  - Gauss points       integration points inside each element
  - Areas              area of every element and the total area
  - Mesh quality       OK / Distorted / Inverted / Degenerate for every element
  - MATLAB export      the .m file the software writes

THE BUG THAT WAS FOUND (images 09 and 12)
  Problem : one folded element was labelled "Distorted" instead of "Inverted",
            because the software only looked at a few points inside each element
            and the fold was between them.
  Fix     : the software now checks more points per element.
  Check   : after the fix, the software and MATLAB both say "Inverted".


SMALL DIFFERENCES THAT ARE NOT ERRORS
  - The total area shown by the software can differ slightly from the exact
    area, for example 15.2146018319 instead of 15.2146018366 for the plate.
    This comes from the standard numerical integration that every IGA program
    uses. MATLAB using the same method gives exactly the same number, and the
    gap shrinks quickly as the mesh is refined (image 11).


PROOF THAT THE CHECKING WORKS
  Seven tiny mistakes were planted on purpose in copies of the results, for
  example one point moved by 0.000001. MATLAB caught all 7.


CONCLUSION
  The software's isogeometric analysis results agree with an independent
  MATLAB calculation for every tested shape and every result type. The one bug
  found was fixed and re-checked. The results are correct.


ABOUT THIS FOLDER
  This folder keeps the 30 final images and this summary from the verification
  run of 24 November 2026. The MATLAB scripts and the CSV tables of numbers
  were removed afterwards to keep the project small, so the run cannot be
  repeated from this folder. The bug fix is still checked by the project's
  own tests (tests/test_iga.py, test_fold_between_gauss_points_is_inverted).
